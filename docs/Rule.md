# RULE.md — Strict Portfolio Asset Replacement Rules

These rules are mandatory.

## RULE 1 — Existing Project Only

Work exclusively inside the existing portfolio project.

Do not create a new portfolio or redesign the existing website.

## RULE 2 — Read Existing Memory

Before implementation:

1. Read the existing root `memory.md`.
2. Understand the current project workflow.
3. Follow existing project instructions.
4. Inspect the current Git status.
5. Identify the correct About section and asset locations.

Do not create duplicate memory files.

After implementation, append the task result to the existing memory according to its established format.

## RULE 3 — My Images Folder

Locate the owner's existing `My Images` folder.

Use only:
- Seven supplied car photographs.
- One supplied favicon.

Do not use another person's photographs.

Do not use stock images, internet images, AI-generated images, or substitute icons.

Do not invent filenames or assets.

## RULE 4 — Seven Car Cards

The existing seven cards must remain seven cards.

Replace only their image sources.

Maintain:
- Existing card positions.
- Existing card dimensions.
- Existing layout.
- Existing sequence.
- Existing swipe functionality.
- Existing animations.

Crop images appropriately.

Never stretch or distort the photographs.

## RULE 5 — Favicon

Use the exact favicon supplied by the owner.

Replace the existing favicon reference.

Ensure it works in Chrome browser tabs.

Do not:
- Create another logo.
- Change the website branding.
- Add another icon.
- Redesign the favicon.

## RULE 6 — No UI Changes

Absolutely no changes to:

- Fonts.
- Colors.
- Typography.
- Layout.
- Card design.
- Spacing.
- Borders.
- Shadows.
- Animations.
- Navigation.
- Responsive behavior.
- Existing functionality.

This is an asset replacement task, not a design improvement task.

## RULE 7 — No Extra Features

Do not add:

- New UI components.
- New sections.
- New animations.
- New interactions.
- AI features.
- Decorative effects.
- New dependencies.
- Unrequested functionality.

Do not refactor unrelated code.

## RULE 8 — Minimal Code Changes

Modify the smallest possible number of files.

Reuse existing components and existing asset-handling methods.

Do not rename or delete unrelated files.

## RULE 9 — Testing

Verify:

1. All seven photographs load.
2. All seven cards display the correct photographs.
3. Swipe navigation works.
4. Cropping looks correct.
5. Favicon loads in Chrome.
6. No broken image references exist.
7. No unrelated functionality has changed.

Run existing build and tests where available.

Never report a test as successful unless it was actually performed.

## RULE 10 — Memory Continuity

After completion, update the existing root `memory.md`.

Record:
- Task completion.
- Seven image filenames.
- Image order.
- Favicon filename.
- Files modified.
- Tests performed.
- Build results.
- Remaining issues.

Preserve all previous memory history.

## FINAL RULE

**Replace the seven car photographs and the favicon. Nothing else.**

The existing portfolio must remain visually and functionally unchanged.
